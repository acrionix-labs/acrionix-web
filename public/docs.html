Acrionix Documentation

Acrionix is an AI-native debugging and patch synthesis platform built for AOSP, Embedded Android, and Linux Kernel teams. It ingests runtime crash logs (logcat, dmesg, tombstones, and avc: denied audits), correlates them against your device tree, and emits minimal, verified git diff patches.

01. Ingest
ADB, Serial & CI

Stream live over USB or triage nightly HIL artifacts.

02. Correlate
BSP Tree Indexing

Indexes .te, init.rc, BoardConfig.mk, and VINTF XML.

03. Patch
Enforcing Safe

Passes CTS neverallow and checkvintf checks.

Quickstart

Install the Python CLI (requires Python 3.10+) and run your first root-cause analysis against a connected ADB device or captured log file.

Install & authenticate 
pip install acrionix-cli
acrionix login
acrionix watch --adb --tree ./device/oem/sm8650

To analyze an existing log file offline or inside CI without a live ADB connection:

Offline log triage 
acrionix triage ./boot_failure.log --tree ./device/oem/common --out fix.patch
git apply --check fix.patch

CLI Reference

acrionix watch [--adb] [--serial ID] [--tree PATH]

Streams live logcat and kernel dmesg over ADB, flags fatal crashes and SELinux denials in real time, and writes minimal patches to ./.acrionix/.

acrionix triage <LOG_PATH> [--open-pr] [--repo ORG/REPO]

Batch-analyzes log archives, tombstones, and kernel panic dumps. With --open-pr, creates a pull request with root-cause citations and unified diff.

acrionix sepolicy audit --strict <SEPOLICY_DIR>

Detects permissive vendor domains, replays captured AVC audit trails, and produces least-privilege .te rules checked against AOSP neverallow rules.

Edge REST API

Call POST https://acrionix.cloud/api/triage directly from CI pipelines, scripts, or IDE extensions to run stateless edge triage on up to 128 KB of runtime logs.

POST https://acrionix.cloud/api/triage 
curl -s -X POST https://acrionix.cloud/api/triage \
  -H "Content-Type: application/json" \
  -d '{"log":"avc: denied { call } for comm=\"vibrator\" scontext=u:r:hal_vibrator_default:s0 tcontext=u:r:servicemanager:s0 tclass=binder permissive=0"}'

Least-Privilege SELinux Synthesizer

Instead of blindly translating every avc: denied line like audit2allow, Acrionix resolves standard AOSP macros (binder_call, r_dir_perms, rw_file_perms) and validates each candidate rule against framework neverallow assertions. 

# Input audit line
avc: denied { call } for comm="android.hardware.vibrator-service"
  scontext=u:r:hal_vibrator_default:s0 tcontext=u:r:servicemanager:s0 tclass=binder

# Synthesized device/oem/common/sepolicy/vendor/hal_vibrator_default.te
+binder_call(hal_vibrator_default, servicemanager)
+allow hal_vibrator_default hal_vibrator_service:service_manager find;

VINTF & HAL Compatibility Resolver

Detects hwservicemanager and AIDL ServiceManagement transport failures, maps the required interface version to your target FCM level, and patches manifest.xml and compatibility_matrix.xml.

Native Crash & Tombstone Triage

Correlates /data/tombstones/tombstone_* C/C++ stack frames, init daemon exit codes, and kernel remoteproc firmware load errors (ENOENT -2) back to the exact device.mk or init.target.rc rule.

GitHub Actions & GitLab HIL CI

Add Acrionix as a post-failure step on your hardware-in-the-loop build runner to automatically open reviewable patch PRs on nightly boot failures.

.github/workflows/hil-triage.yml 
- name: Triage HIL Boot Failure
  if: failure()
  env:
    ACRIONIX_API_KEY: ${{ secrets.ACRIONIX_API_KEY }}
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    pip install acrionix-cli
    acrionix triage ./artifacts/hil-logs --tree ./device/oem --open-pr

Security & Zero Data Retention

Customer device trees, proprietary SoC manifests, and runtime logs are never used to train shared models. Enterprise OEM deployments support fully air-gapped on-premise containers with local model inference.
